3. AVANTAGES DE L'IMPLÉMENTATION
=================================================================================

CENTRALISATION:
---------------
• Toute la logique de validation est centralisée dans les Form Requests
• Plus besoin de répéter Validator::make() dans les controllers
• Les règles de validation sont réutilisables et maintenables

SÉCURITÉ:
---------
• Validation automatique avant l'exécution du controller
• Authorization intégrée dans authorize() des Form Requests
• Validation des rôles (Admin, Manager, SuperAdmin) dans les Form Requests

LISIBILITÉ:
-----------
• Code des controllers plus propre et concis
• Séparation claire entre validation et logique métier
• Documentation claire avec PHPDoc sur chaque Form Request

MAINTENABILITÉ:
---------------
• Facile à modifier les règles de validation (un seul endroit)
• Facile à ajouter de nouvelles règles
• Réduction significative de la duplication de code

MESSAGES D'ERREUR:
------------------
• Messages d'erreur en français personnalisés dans messages()
• Cohérence des messages à travers toute l'API
• Messages contextuels et compréhensibles

=================================================================================
4. STRUCTURE DES FORM REQUESTS
=================================================================================

Chaque Form Request contient:

1. authorize() - Détermine si l'utilisateur est autorisé
   • Vérifie l'authentification (Auth::check())
   • Vérifie les rôles (Role::ADMIN, Role::MANAGER, etc.)
   • Retourne true/false

2. rules() - Définit les règles de validation
   • Règles Laravel standard (required, numeric, email, etc.)
   • Règles custom (regex pour téléphone sénégalais)
   • Règles conditionnelles
   • Validation de fichiers (images, dimensions, taille)

3. messages() - Messages d'erreur personnalisés en français
   • Un message pour chaque règle
   • Messages clairs et contextuels
   • Format unifié

5. EXEMPLES D'UTILISATION
=================================================================================

AVANT (avec Validator::make):
------------------------------
public function signup(Request $request)
{
    $validator = Validator::make($request->all(), [
        'first_name' => ['required', 'regex:#^[\p{L}]+[\p{L} ]*$#u', 'max:255'],
        'email' => ['required', 'email', 'unique:users'],
        'password' => ['required', 'confirmed', Password::min(8)]
    ]);
    
    if($validator->fails()) {
        return response()->json(['message' => $validator->errors()->first()], 422);
    }
    
    // Logique métier...
}

APRÈS (avec Form Request):
--------------------------
public function signup(SignupRequest $request)
{
    // Validation automatique - pas besoin de vérifier
    // Logique métier directement...
}

6. VALIDATION DES DONNÉES
=================================================================================

TÉLÉPHONES SÉNÉGALAIS:
----------------------
Regex: #(^3[3]|^7[5-80])[ ]?[0-9]{3}([ ]?[0-9]{2}){2}$#
Format: 33 123 45 67 ou 77 123 45 67

EMAILS:
-------
Regex: #^[^\s@]+@[^\s@]+\.[^\s@]+$#

NOMS (Unicode):
---------------
Regex: #^[\p{L}]+[\p{L} ]*$|^[\p{L} ]+[\p{L}]+[\p{L} ]*$#u
Accepte: lettres de tous alphabets + espaces

MOTS DE PASSE:
--------------
Rules\Password::min(8)
Minimum 8 caractères + confirmation obligatoire

IMAGES:
-------
- Types: jpeg, jpg, png, webp
- Taille max: 1024 Ko (1 Mo)
- Dimensions min: 200x200 px (avatars) ou 256x256 px (produits)

PRIX/POIDS:
-----------
'numeric', 'decimal:0,2'
Maximum 2 décimales

9. NOTES IMPORTANTES
=================================================================================

• Les Form Requests sont automatiquement validés AVANT l'exécution du controller
• En cas d'échec de validation, Laravel retourne automatiquement une réponse 422
• L'authorize() est appelé avant les rules()
• Les données validées sont automatiquement disponibles dans $request
• Les Form Requests peuvent être testés unitairement
